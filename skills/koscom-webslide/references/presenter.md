# 대본과 발표자 보기 — PPT처럼 발표하기

덱에는 장마다 **대본**(발표자 노트)을 넣는다. 청중 화면에는 보이지 않고, 발표할 때 `S`를 누르면 PPT 발표자 보기처럼 새 창에 현재 장·다음 장·대본·경과 시간이 뜬다. 두 창은 함께 넘어가고 발표 리모컨(무선 클리커)으로 넘길 수 있다. 네 원고 원본 모두 같은 블록을 쓴다.

## 발표하는 순서 (화면 두 개)
1. 덱(최종본 `_verN.html` 또는 스튜디오의 「덱 열고 고치기」)을 Chrome·Edge로 연다.
2. `S` — 발표자 창이 열린다. 팝업이 막히면 주소창 오른쪽에서 팝업을 허용하고 `S`를 다시 누른다.
3. 청중 창을 프로젝터 화면으로 옮기고(`Win`+`Shift`+`→`) `F`로 전체 화면. 발표자 창은 노트북 화면에 둔다.
4. 넘기기: `→` `PgDn` `Space` 다음, `←` `PgUp` 이전, `Home` `End`. **어느 창에 초점이 있어도** 두 창이 함께 넘어간다. 발표자 창의 「이전」「다음」 단추도 같다.
5. 발표자 창: 경과 시간(`P` 일시정지, `R` 다시 재기)·현재 시각, 대본 글자 크기 `가−` `가+`(`-` `+`, 다음에도 기억).

## 리모컨(클리커)
USB 수신기를 꽂는 일반 발표 리모컨이면 설정 없이 된다.

| 리모컨 단추 | 보내는 키 | 동작 |
|---|---|---|
| 다음 · 이전 | `PgDn` · `PgUp` | 장 넘김(두 창 모두) |
| 화면 끄기 | `B` 또는 `.` | 청중 화면을 검게 가림, 다시 누르면 돌아옴. 발표자 창에 「화면 가림 중」 표시 |
| 슬라이드 쇼 시작 | `F5` | 청중 창 전체 화면(브라우저 새로 고침을 막는다). 발표자 창에서는 무시 |
| 레이저 | — | 리모컨 자체 기능 |

휴대폰을 리모컨으로 쓰는 기능은 넣지 않았다(서버·같은 망이 필요해서).

## 화면이 하나일 때 · 리허설
`N` — 지금 장의 대본을 화면 아래에 펼친다(청중도 보이니 리허설용). 다시 `N`으로 닫는다. 대본이 없는 장이면 알림이 뜬다.

## 대본 고치기
편집 모드 `E` → `N`으로 대본을 펼친다 → 대본 문단을 눌러 고친다 → 「HTML 저장」. 스튜디오에서 연 덱이면 `deck/index.html`에 바로 저장된다. 발표자 창이 열려 있으면 고치는 대로 바뀐다.

## 대본 쓰기 (에이전트)
장마다 `</section>` 바로 앞에 둔다. 부록(`aside.side-page`)에는 쓰지 않는다(질문 받을 때 여는 곳).
```html
  <section class="slide" data-sec="1" data-label="문제 · 보고서 시간">
    …
    <aside class="notes">
      <p>업무시간의 <strong>35%</strong>가 보고서에 들어갑니다.</p>
      <p>이 숫자는 사람인이 직장인 1,227명에게 물은 외부 조사입니다. 우리 회사 실측은 아닙니다.</p>
      <p>그럼 이 시간이 어디서 새는지 다음 장에서 보겠습니다.</p>
    </aside>
  </section>
```
- **분량**: 1분에 약 300자로 잡는다. 발표 시간 ÷ 장 수로 장당 시간을 정한다(10분·8장이면 장당 300~400자). 표지·마무리는 짧게.
- **첫 문단** — 이 장의 결론 한 문장. 제목을 그대로 읽지 않고 말로 풀어 쓴다.
- **가운데** — 화면에 없는 것: 왜 그런지, 숫자의 성격(실측·외부 조사·가정), 예 하나. 화면의 글을 다시 읽지 않는다.
- **끝 문단** — 다음 장으로 넘기는 한 문장(다음 장 제목과 이어지게). 마지막 장은 요청할 결정과 질문 받기.
- **말투** — 사람 앞에서 하는 존댓말(~입니다·~습니다). 개조식(~함·~임), 괄호 설명, 문어 접속어(따라서·또한·이에·한편)는 쓰지 않는다 → 그래서·그리고·그런데.
- **강조** — 장마다 핵심어 2~3개만 `<strong>`. 문단은 1~3문장.
- **숫자** — `facts/`에 있는 값만. `voice_tool.py gate`가 대본의 숫자도 근거와 대조한다(대본은 제목·장당 분량 같은 문체 지표에는 넣지 않는다). 가정한 숫자는 "가정하면"이라고 말한다.
- 문체 폴더(`voice/`)가 있으면 그 표기(숫자·단위·용어)를 대본에도 쓴다.

## 구조 (원본을 고칠 때)
- CSS — 엔진 CSS 끝(첫 `</style>` 앞)의 「대본(발표자 노트)」 블록: `.slide aside.notes`를 숨기고 `body.notes-on`일 때 지금 장의 대본을 펼친다. `body.kp-black`(화면 가림), `html.kp-preview`(미리보기: 커서·알림·편집 막대 숨김, 등장 움직임 없음).
- JS — `</body>` 바로 앞의 「발표자 보기(S)·대본(N)」 블록. `window.deck`(`go`·`index`·`slides`·`N`·`toast`)과 `deck:slide` 이벤트만 쓴다.
- 미리보기 — 발표자 창의 두 미리보기는 같은 파일을 `?preview#N`으로 띄운 것이라 청중 화면과 똑같다([lewislulu/html-ppt-skill](https://github.com/lewislulu/html-ppt-skill), MIT 방식). 장을 바꿀 때는 다시 읽지 않고 `postMessage`로 그 장으로 간다. 그래서 덱을 두 번 더 여는 셈이다(3D 원본은 그래픽 부담이 크다).
- 발표자 창은 청중 창의 스크립트가 쓰고 움직인다. 청중 창을 닫거나 새로 고치면 같이 닫히니 `S`를 다시 누른다.
- 네 원본의 이 두 블록과 엔진은 글자 하나까지 같아야 한다(`studio_selftest.py` 1단계가 확인).

## 검사
`check_deck.js`(최종본을 만들 때 함께 돈다)가 확인한다:
- 대본이 있는 장 수(`대본: 7/8장`), `N` 펼침
- `S` 발표자 창이 열리는지, 발표자 창에서 `PgDn`·`PgUp`을 누르면 청중 화면·현재 장·다음 장 미리보기가 함께 넘어가는지

`--shots`를 주면 `presenter.png`도 남는다. 대본이 빠진 장은 실패로 치지 않으니 장 수를 보고 채운다.
