# 원고 구성 — 예시 덱(23장)의 흐름

공모전·사내 기획서에 맞춘 흐름이다. 분량에 맞게 장을 빼고 합친다.

| 묶음 | 장 | 메시지 | 부품 |
|---|---|---|---|
| 시작 | 1 표지 | 이름 · 한 줄 정의 · ★핵심 기능 한 줄 · 형식 꼬리표 · 버튼 | `.cover`, 코쇠 아바타 |
| | 2 한 장 요약 | 문제·해법·★핵심·증거·효과 5칸 — 평가자가 여기서 판단한다 | `.sum5` + `.agenda.mini`(레일이 읽음) + 근거 배지 범례 |
| 01 문제 | 3 크기 | 제목에 숫자: "업무시간의 35%, 보고서에 씁니다" | 막대·도넛 차트, `.kpi` 3개 |
| | 4 장면 | 사람들이 실제로 겪는 장면 | 삽화 + 번호 목록 |
| | 5 Before/After | 지금 흐름 vs 바뀐 흐름 | `.ba` 두 줄 흐름 + 카드 3 |
| | 6 선례 | 이미 도입된 방향 | 막대 + 사례 카드 |
| 02 해법 | 7 한 줄 | 해법을 한 문장으로 + ★ | 어두운 장 + 큰 삽화 |
| | 8 구조 | 요청 → 형식·양식 선택 → 엔진 | 구조도(SVG) + `.rule` |
| 03 증거·무엇 | 9 증거 | "이 기획서가 증거입니다" — 이미 있는 것 / 본선에서 만들 것 | `.proof3` 썸네일 3 |
| | 10~14 | 구성 요소마다 한 장 + 공통 설계 (제목에 기록 숫자) | 기록 차트, 실물, 코드 |
| 04 운영 | 15~18 | 구성 · ★핵심 기능(대표 문서 → 스킬 자동 생성 → 검증 → 관리자 등록) · 상속 · 사람의 승인 | 탭, 단계 흐름(`.pipe`), 코드, 검증 목록(`.chk`), 층 |
| 05 실행 | 19 시연 3분 | 심사위원이 기억할 장면 | 자동 재생 타임라인 |
| | 20 준비·일정 | 보유한 것과 할 것, 일정 | `.ready` + 간트 |
| | 21 효과 | 숫자를 실감 단위로(연 24,000시간 = 12명의 1년, 가정) | 누적 차트 + `.fact` |
| | 22 심사 기준 | 기준별 답 | 배점 차트 + 카드 |
| 끝 | 23 맺음 | 다짐 한 문장 + 꼬리표 | 검은 장 + 물결 |

부록: A 수치 근거 · B 출처 · C 예상 질문 · D 실물 · E 요약 영상 · F 화면 시안·준비

## 문장 원칙
- 제목은 결론 한 문장(명사형이 아니라 말하는 문장). 강조 낱말 하나만 `<em>`
- 설명은 짧게, 근거는 부록으로. 한 장에 메시지 하나
- 숫자는 성격을 밝힌다 — 주의 문장을 장마다 반복하지 말고 `.ev` 배지(외부 조사·제공업체 발표·기존 기록·가정·목표·가상)로 붙이고, 구분 원칙은 부록 A에 한 번 쓴다
- 숫자 세기(`data-count`)의 처음 글자는 최종값으로 둔다 — 인쇄·캡처에서 0이 보이지 않게
- 공모전·심사용이면 규정을 먼저 확인한다(예: 서류 단계에서 할 수 있는 일, 사전 보유 자산 표기, 용량 제한)
