# 원고 구성 — 예시 덱(21장)의 흐름

공모전·사내 기획서에 맞춘 흐름이다. 분량에 맞게 장을 빼고 합친다.

| 묶음 | 장 | 메시지 | 부품 |
|---|---|---|---|
| 시작 | 1 표지 | 이름 · 한 줄 정의 · 형식 꼬리표 · 버튼(펼치기·요약 영상·부록) | `.cover`, 코쇠 아바타 |
| | 2 목차 | 다섯 장면 | `.agenda` |
| 01 문제 | 3 크기 | 문제는 이미 조사로 확인됐다 | 막대·도넛 차트, `.kpi` 3개 |
| | 4 장면 | 사람들이 실제로 겪는 장면 | 삽화 + 번호 목록 |
| | 5 경쟁 | 무엇이 차별점이 아닌가 | 산점도(포지셔닝) |
| | 6 선례 | 이미 검증된 방향 | 막대 + 사례 카드 |
| 02 해법 | 7 한 줄 | 해법을 한 문장으로 | 어두운 장 + 큰 삽화 |
| | 8 구조 | 요청 → 라우터 → 엔진 | 구조도(SVG) + `.rule` |
| 03 무엇 | 9~13 | 구성 요소마다 한 장 + 공통 설계 | 실측 차트, 실물, 코드 |
| 04 운영 | 14~16 | 등록 · 상속 · 사람의 승인 | 탭, 층, 단계 |
| 05 실행 | 17 시연 3분 | 심사위원이 기억할 장면 | 자동 재생 타임라인 |
| | 18 준비·일정 | 보유한 것과 할 것, 일정 | `.ready` + 간트 |
| | 19 효과 | 숫자와 숫자 밖의 효과 | 누적 차트 + `.fact` |
| | 20 심사 기준 | 기준별 답 | 배점 차트 + 카드 |
| 끝 | 21 맺음 | 한 문장 + 꼬리표 | 검은 장 + 물결 |

부록: A 수치 근거 · B 출처 · C 예상 질문 · D 실물 · E 요약 영상 · F 화면 시안·준비

## 문장 원칙
- 제목은 결론 한 문장(명사형이 아니라 말하는 문장). 강조 낱말 하나만 `<em>`
- 설명은 짧게, 근거는 부록으로. 한 장에 메시지 하나
- 숫자는 성격을 밝힌다(실측·외부·가정). 남의 수치는 '벤더 발표'처럼 출처 성격까지
- 공모전·심사용이면 규정을 먼저 확인한다(예: 서류 단계에서 할 수 있는 일, 사전 보유 자산 표기, 용량 제한)
