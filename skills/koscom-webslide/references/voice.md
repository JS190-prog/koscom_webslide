# 문체 맞추기 — 대표 자료를 분석하고, 그 문체로 쓰고, 스크립트로 검사한다

[gn-voice](https://github.com/gongnyang/gn-voice)의 방식(서식을 걷어낸 본문 → 문체 지표 → 허용 범위(밴드) → 스크립트 검사 → 고칠 항목)과
presentation 프로필의 장표 자기검증(제목만 읽기 · 장당 단어 수 · 항목 병렬성)을 덱에 맞게 옮겼다.
대표 자료 2~3건으로도 돌게 줄인 뼈대는 `koscom-hwp-report` 스킬의 문체 도구와 같다. gn-voice 저자의 글·지문 데이터는 쓰지 않는다.

```
대표 자료 ─(voice_tool build)→ voice/style-guide.md ─(원고 설계에 덧입힘)→ index.html ─(voice_tool gate)→ 고칠 항목 → 합격 → 단일 파일
```

## 1. 분석 (`build`)

```bash
python scripts/voice_tool.py build 예전발표1.pptx 예전발표2.html 메모.md --out ./voice --type 사업설명회 --human
```

- 읽는 형식: 웹슬라이드 `.html`(이 스킬로 만든 덱이나 `<section>`으로 장을 나눈 HTML) · `.pptx` · `.hwpx`(한글 보고서·기안문, 장 구분이 없어 한 장으로 본다) · `.md`(`#`·`##` 제목 또는 `---`로 장 구분) · `.txt`. `.ppt`는 `.pptx`로, `.hwp`는 한글에서 `.hwpx`로 저장하고, 워드·PDF는 본문을 `.txt`로 저장해 넣는다. 한글 문서의 표·글상자 안 글은 문체 측정에서 빠지고 숫자 대조(`--facts`)에는 들어간다. 본문이 표 안에만 있는 문서(견적서 등)는 표 안 글을 본문으로 읽는다.
- 한글 보고서만 대표 자료로 주면 장 구분이 없어 제목·장 분량 지표는 만들어지지 않는다. 본문 끝맺음·길이·표기만 맞추고, 제목·장 분량은 `storyline.md`의 문장 원칙을 따른다. `.pia`(사내 암호화)는 해제한 뒤 넣는다.
- **사람이 직접 쓴 자료만** 넣는다. AI가 쓴 덱을 넣으면 기준이 AI 문체가 된다. 사용자가 말하지 않았으면 한 줄로 확인하고 `--human`을 붙인다.
- 같은 쓰임(발표용끼리, 보고·회람용끼리) 2~3건이 알맞다. 1건이면 `문체 시험용(1건)`이라 검사는 참고만 된다.
- 출력 JSON의 `label`·`status`·`leave_one_out`과 `rules`를 사용자에게 알린다. `문체 미검증`이면 자료끼리 문체가 다르다는 뜻이다(예: 발표용 웹슬라이드와 시설 보고용 PPT를 섞음). 같은 쓰임으로 다시 고르라고 안내한다.
- 만들어지는 것: `style-guide.md`(사람과 에이전트가 읽는 분석 결과), `style-profile.json`, `fingerprint-slim.json`(검사 밴드), `ai-tells.json`, `manifest.jsonl`, `corpus/`(서식을 걷어낸 장별 글).
- **분석만** 원하면 `style-guide.md`의 "1. 이렇게 쓴다"와 "2. 제목"을 요약해 보여 주고 파일 경로를 알린 뒤 끝낸다.
- `style-guide.md`와 `corpus/`에는 대표 자료 문장이 그대로 들어 있다. 공유하기 전에 개인정보를 확인하라고 알린다. 문체 폴더는 덱 폴더 밖에 둔다(단일 파일에 섞이지 않게).

### 무엇을 재나

| 묶음 | 지표 | 뜻 |
|---|---|---|
| 제목(5개 묶음) | 제목 길이 · 서술어로 끝나는 제목 비율 | 결론 문장형 제목(`~씁니다`, `~한다`)인지, 명사형·말줄임(`~ 현황`, `~으로`)인지 |
| 장 | 장당 본문 어절 수 · 장 안 항목 끝맺음 일치도 | 장표의 글 양, 항목끼리 같은 꼴로 끝나는지(병렬성) |
| 본문(5줄 묶음) | 끝맺음 4종 비율 · 줄 길이와 들쭉날쭉함 · 마침표·쉼표·괄호 밀도 | 줄을 무엇으로 끝내고 얼마나 길게 쓰는지 |

`style-guide.md`에는 이 밖에 자주 쓴 제목 끝말·본문 끝말, 쉼표로 나눈 제목·숫자 든 제목 비율, 제목 강조(`<em>`) 개수, 나열 기호(`·` `→`), 날짜·금액·증감 표기, 자주 쓴 두 어절 표현, 원문 그대로의 제목 예와 본문 예문이 들어간다.

### 무엇을 빼고 읽나 (대표 자료와 검사할 덱이 같은 규칙)

| 요소 | 문체 측정 | 숫자 대조 |
|---|---|---|
| 장 제목(`h1`·`h2`, `.pptx` 제목 개체) · 장 안의 글 | 들어감 | 들어감 |
| 근거 배지 `.ev` · 장 번호 `.no` · 영문 꼬리표 `.kick` · 목차 `.agenda` · 버튼(요약 카드 포함) · `[data-gen]` · 표지 셰브론 · 상단 바 | 빠짐 | 빠짐 |
| 표(`table`, `.pptx` 표) · 코드(`pre`) · 부록(`.side-page`) · 차트 데이터(`deck-data`) | 빠짐 | 들어감 |
| 숨긴 슬라이드 · 쪽 번호·날짜·바닥글 개체 · 발표자 노트 | 빠짐 | 빠짐 |

- 편집 모드가 글로 보지 않는 요소(`template/index.html`의 `SKIP`)를 그대로 따른다. 버튼 안 숫자는 대조되지 않으니, 같은 숫자를 본문에도 쓰거나 눈으로 확인한다.
- 제목 개체를 쓰지 않은 `.pptx` 장(사내 덱에 흔함)은 한글이 든 60자 이하 첫 문단 중 가장 큰 글자를 제목으로 본다.
- 8자 미만이거나 한글이 없는 줄(꼬리표, 숫자, 영문 라벨)은 끝맺음 측정에서 빠지고 장당 어절 수에는 센다.

## 2. 그 문체로 쓰기 (원고 설계 · 장 쓰기)

`style-guide.md`의 "1. 이렇게 쓴다", "2. 제목"의 제목 예, "8. 본문 예문"을 읽고 원고에 덧입힌다. 둘이 다르면 이렇게 정한다.

- **웹슬라이드 규칙이 이긴다**: 서체·색·무대, 한 장에 메시지 하나, 근거 배지·부록, 가상 데이터, 원문에 없는 숫자 금지
- **문체 가이드가 이긴다**: 제목을 문장으로 끝낼지 명사형으로 끝낼지, 제목 길이·쉼표 구조·강조 개수, 장당 글 양, 본문 끝맺음·끝말·마침표, 나열 기호, 날짜·금액·증감 표기, 자주 쓴 표현
- 가이드가 명사형 제목이면 따르되, 제목 아래 `.lead`에 결론 한 문장을 둔다(gn-voice presentation의 리딩덱 규칙). `references/storyline.md`의 "제목은 결론 한 문장"보다 가이드가 우선한다.
- 표기는 가이드를 따르되 **숫자 값은 근거 그대로** 둔다. `2026.4`처럼 표기를 바꾸는 것은 되지만 `2,400만원`을 `0.24억원`으로 환산하면 gate가 불합격시킨다.
- 대표 자료가 없으면 이 절을 건너뛰고 `storyline.md`의 문장 원칙만 따른다.

## 3. 검사 (`gate`) — 장을 다 쓴 뒤, 단일 파일을 만들기 전에

1. 근거 파일 `facts.txt`를 만든다: 사용자 요청문과 받은 자료의 숫자·이름(기간, 금액, 인원, 비율, 제품명). 덱의 숫자(본문·차트 데이터·부록)는 모두 여기에 있어야 한다.
2. 덱을 검사한다.
   ```bash
   python scripts/voice_tool.py gate --voice ./voice --facts facts.txt ./my-deck/index.html
   ```
   - 종료 코드 0이면 합격, 3이면 불합격이다. JSON의 `rework`에 고칠 항목이 한 줄씩 나온다.
   - `[금지]`는 그 표현을 뺀다. `[문체]`는 지표가 높으면 줄이고 낮으면 늘린다. 장 단위 지표(제목 길이·제목 끝맺음·장당 어절)는 어느 장 때문인지 `— 7장 「…」`로 짚어 준다. `[숫자]`는 근거대로 고치거나 `[확인 필요]`로 쓴다.
   - `titles`를 위에서 아래로 읽는다. 제목만 읽어도 이야기가 이어지는지 본다(gn-voice presentation의 타이틀만 읽기 테스트). 끊기면 제목을 고친다.
   - `unused_facts`는 쓰지 않은 근거라 참고만 한다.
3. **`rework`에 나온 항목만** 고친다. 합격한 문장과 숫자는 건드리지 않는다. **최대 2번** 고치고, 그래도 불합격이면 남은 항목을 그대로 보고하며 합격이라고 하지 않는다.
- 문체 폴더가 없으면 `--voice` 없이 돌린다. 상투구·이모지와 숫자 대조만 한다.
- 기존 발표자료를 웹슬라이드로 옮기는 경우는 `--mode rewrite --facts 원본.pptx`를 쓴다. 원본에 있던 숫자가 사라져도 불합격이다.
- 단일 파일(`*_단일파일.html`)도 같은 규칙으로 읽힌다(예시 덱의 폴더판과 `build_single.py` 결과가 장·제목·본문·숫자 대조 글·지표까지 같게 읽힘을 확인함).

## 4. 고쳤을 때

`scripts/voice_tool.py`를 고쳤으면 `python scripts/voice_selftest.py`를 돌린다(표준 라이브러리만, 수 초).

## 한계

- 형태소 분석기 없이 정규식으로 끝맺음을 센다. gn-voice 원본(kiwipiepy)처럼 정밀하지 않다.
- 확인한 범위: 예시 덱(웹슬라이드), 사내 시설 발표자료 `.pptx` 3건(같은 문체 3건은 한 건 빼고 검증 통과, 웹슬라이드와 섞으면 `문체 미검증`), 합성 덱. 여러 작성자의 실제 발표자료로는 아직 재 보지 않았다.
- 문체를 가르는 도구다. 내용이 맞는지, 장 구성이 설득력 있는지는 사람이 본다.
